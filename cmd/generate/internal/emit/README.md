# emit

## Overview

Package `emit` renders the generated Go files of the root `acp` package with jennifer (`github.com/dave/jennifer/jen`).
Each exported `Write*Jen` function builds one or two jennifer files for package `acp` and writes them into `outDir`.
The inputs are `load.Meta` and `load.Schema` from `github.com/coder/acp-go-sdk/cmd/generate/internal/load`, and the method grouping comes from `github.com/coder/acp-go-sdk/cmd/generate/internal/ir`.
`jenwrap.go` re-exports jennifer names under short aliases so the emitter does not need a dot-import.

## Interface

- `WriteConstantsJen(outDir string, meta *load.Meta) error` writes `ProtocolVersionNumber` and the `AgentMethod<Name>` and `ClientMethod<Name>` constants to `constants_gen.go` [constants.go:WriteConstantsJen]
- `WriteTypesJen(outDir string, schema *load.Schema, meta *load.Meta) error` writes every schema type plus the `Agent`, `AgentExperimental`, `Client`, and `ClientExperimental` interfaces to `types_gen.go`. It also writes `AgentLoader` and `ClientTerminal` when they have methods [types.go:WriteTypesJen]
- `WriteDispatchJen(outDir string, schema *load.Schema, meta *load.Meta) error` writes `agent_gen.go` (the `AgentSideConnection.handle` switch and the agent-to-client wrappers) and `client_gen.go` (the `ClientSideConnection.handle` switch and the client-to-agent wrappers) [dispatch.go:WriteDispatchJen]
- `WriteHelpersJen(outDir string, schema *load.Schema, _ *load.Meta) error` writes one `New<Union><Variant>` constructor per variant of each eligible `oneOf` union to `helpers_gen.go` [helpers.go:WriteHelpersJen]
- Type aliases `Code`, `Dict`, `Group`, and `File` for the jennifer types of the same name [jenwrap.go:Code, Dict, Group, File]
- Function variables that alias jennifer functions: `NewFile`, `Id`, `Lit`, `Line`, `Func`, `For`, `Range`, `Return`, `Nil`, `String`, `Int`, `Float64`, `Bool`, `Any`, `Map`, `Index`, `Qual`, `Error`, `Case`, `Default`, `Switch`, `Var`, `If`, `List`, `Op`, `InterfaceFunc`, `Comment` [jenwrap.go:NewFile]
- All other functions are unexported. The `j*` helpers build the bodies of the generated `handle` switch cases [dispatch_helpers.go:jUnmarshalValidate, jAgentAssert, jClientAssert, jSingleMethodAssert]

## Invariants

- Every generated file declares package `acp` and starts with the header `Code generated by acp-go-generator; DO NOT EDIT.` [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]
- Method keys, definition names, and struct property names are sorted before emission [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]. The union property scans use sorted keys too: the string-const properties that a variant's `MarshalJSON` injects, and the fallback discriminator scan described below. Output does not depend on Go map iteration order [types.go:emitUnion, sortedPropertyKeys, firstConstPropertyKey] [union_test.go:TestWriteTypesJen_MultiConstUnionIsDeterministic]
- Method constant names are `AgentMethod` or `ClientMethod` plus `toExportedConst(key)`, which title-cases each `_`-separated part of the meta key. The dispatch switch cases use the same names, so the two files must stay in step [constants.go:toExportedConst] [dispatch.go:WriteDispatchJen]
- Dispatch skips a meta method that has no group in `ir.BuildMethodGroups`, and skips a switch case whose body is empty. Unknown methods reach the `default` case, which returns `NewMethodNotFound` [dispatch.go:WriteDispatchJen]
- Each generated handler case unmarshals `params` into the Request or Notification type and calls `Validate()`. A failure in either step returns `NewInvalidParams` [dispatch_helpers.go:jUnmarshalValidate, jInvInvalid]
- Errors from the agent or client method are wrapped with `toReqErr` [dispatch_helpers.go:jRetToReqErr]
- `BindAgentLoader` methods assert `AgentLoader`, `BindClientTerminal` methods assert `ClientTerminal`, and experimental methods assert a one-method anonymous interface. A failed assertion returns `NewMethodNotFound` [dispatch_helpers.go:jAgentAssert, jClientAssert, jSingleMethodAssert]
- The response type name is the request name with `Request` replaced by `Response`. When `ir.IsNullResponse` is true for that definition, the interface method returns only `error` and the outbound wrapper calls `SendRequestNoResult` [dispatch.go:WriteDispatchJen] [types.go:WriteTypesJen]
- The generated agent `session/prompt` case derives `context.WithCancel(ctx)`, calls `registerPrompt`, calls the agent with the derived context, and then deletes the `sessionCancels` entry while holding `a.mu` [dispatch.go:WriteDispatchJen]
- The generated agent `session/cancel` case calls `a.cancelPrompt` for the session after validation and before the agent's `Cancel` method [dispatch.go:WriteDispatchJen]
- The generated client `Prompt` wrapper sends `Cancel` with `context.Background()` and ignores its error when the request fails and `ctx.Err()` is non-nil [dispatch.go:WriteDispatchJen]
- Outbound notification wrappers are named `SessionUpdate` for `session/update` and `Cancel` for `session/cancel`. Other names drop the `Notification` suffix, and request wrappers drop the `Request` suffix [dispatch.go:WriteDispatchJen]
- `WriteTypesJen` registers every schema definition name in `usedTypeNames` before emission. Nested and variant names come from `generateNestedTypeName`, and a name collision or an unregistered variant panics with a `BUG` message [types.go:WriteTypesJen, generateNestedTypeName, emitUnion]
- An `enum`, a `oneOf` of string consts, or an "open" `anyOf` of plain string schemas with at least one string const becomes a named `string` type with constants, not a union wrapper [types.go:WriteTypesJen, isStringConstUnion, isOpenStringEnum]
- Optional struct fields get a `json:",omitempty"` tag option. Required fields do not. Exception: in a top-level struct, an optional array or object field whose default is nilable (a slice or map) gets no `omitempty`, so it is always present. Nested inline structs and union variant structs always use `omitempty` for optional fields [types.go:WriteTypesJen, emitUnion]
- A top-level struct with schema defaults gets generated `MarshalJSON` and `UnmarshalJSON`. `UnmarshalJSON` applies the default when the key is missing, or when the value is `null` and the schema type does not include `null`. Nested inline structs and union variant structs get no default handling [types.go:WriteTypesJen, emitUnion]
- A union wrapper has one pointer field per variant with tag `json:"-"`. Its `UnmarshalJSON` tries a `null` variant, then the discriminator, then required object keys, then required keys of array items, then each variant in order. If nothing matches, it returns `no matching variant for union` [types.go:emitUnion]
- A `oneOf` union also gets `Validate`, which returns an error unless exactly one variant is set [types.go:emitUnion]
- An inline variant struct (a variant without `$ref`) also gets the parent union's own properties and required keys [types.go:emitUnion]
- A union's `MarshalJSON` re-encodes the set variant and injects its string-const properties. For `ContentBlock`, it rebuilds each of the `text`, `image`, `audio`, `resource_link`, and `resource` payloads with a fixed key set, and the `image` case writes `uri` only when it is set [types.go:emitUnion]
- A definition that matches no other case becomes `type <Name> any` with the comment "is a union or complex schema; represented generically". An object schema with no properties becomes an empty struct [types.go:WriteTypesJen]
- A title-only variant whose description contains "extension" or whose title contains `Ext` becomes an alias of `json.RawMessage`, so the raw payload is kept. A variant with no `$ref`, no properties, no `null` type, and no title is skipped [types.go:emitUnion]
- `Validate` is generated for `ToolCallUpdate`, and for non-`oneOf`-union types named `*Request`, `*Response`, or `*Notification` whose primary schema type is `object`. Types such as `AgentResponse`, `ExtRequest`, `ExtResponse`, and `ExtNotification` match the names but get no `Validate`. It checks that required string fields are non-empty and required array fields are non-nil. `ToolCallUpdate.Validate` returns `toolCallId is required` when `ToolCallId` is empty [types.go:WriteTypesJen, emitValidateJen]
- `AgentExperimental` and `ClientExperimental` are always emitted, even when empty. `AgentLoader` and `ClientTerminal` are emitted only when they have methods [types.go:WriteTypesJen]
- Interface method doc comments are omitted when the method is `DocsIgnored` [types.go:methodDescription]
- `WriteHelpersJen` skips definitions that are nil, have `DocsIgnore`, have no `oneOf`, are string-const unions, or are named `ContentBlock`, `ToolCallContent`, or `SessionUpdate`. The hand-written helpers for those three live in https://github.com/coder/acp-go-sdk/blob/main/helpers.go [helpers.go:WriteHelpersJen]
- `WriteHelpersJen` builds the types once (`buildTypesJen`) and emits one constructor per `oneOf` variant that `emitUnion` recorded, with the field, type, and discriminator that `emitUnion` chose. So every constructor builds a type that `types_gen.go` declares, also when a generated nested name forced a fallback variant name [helpers.go:WriteHelpersJen] [types.go:buildTypesJen, emitUnion] [union_test.go:TestWriteHelpersJen_UsesUnionVariantTypes]
- `emitUnion` skips a phantom variant (no `$ref`, no properties, no `null` type, and no title, `isPhantomVariant`) after registering its name, and records nothing for it, so no constructor is generated for it [types.go:isPhantomVariant, emitUnion] [union_test.go:TestWriteHelpersJen_SkipsPhantomVariant]
- Without an explicit `discriminator.propertyName`, the discriminator key is the first `const` property, in sorted key order, of the first expanded variant that has one [types.go:firstConstPropertyKey, emitUnion]
- `expandAllOf` copies the definition, its `Properties` map, and its `Required` slice before merging, so it does not change its input [types.go:expandAllOf]

## Side Effects

- Writes `constants_gen.go`, `types_gen.go`, `agent_gen.go`, `client_gen.go`, and `helpers_gen.go` into `outDir` with `os.WriteFile`. A missing file is created with mode `0o644` (before umask). An existing file is truncated and keeps its permissions [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]
- `WriteDispatchJen` writes `agent_gen.go` before it renders `client_gen.go`, so a later failure leaves `agent_gen.go` written [dispatch.go:WriteDispatchJen]
- Returns render and write errors to the caller [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]
- Panics on internal type-name collisions or when no unique nested name exists [types.go:generateNestedTypeName, emitUnion]
- No network, subprocess, environment, goroutine, or lock use in the emitter itself. At run time, the generated code locks `a.mu`, calls the generic function `SendRequest[T](c.conn, ...)`, and calls the methods `c.conn.SendNotification` and `c.conn.SendRequestNoResult` [dispatch.go:WriteDispatchJen]
