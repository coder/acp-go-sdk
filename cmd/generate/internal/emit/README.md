# emit

## Overview

Package `emit` renders the generated Go files of the root `acp` package with jennifer (`github.com/dave/jennifer/jen`).
Each exported `Write*Jen` function builds one or two jennifer files for package `acp` and writes them into `outDir`.
The inputs are `load.Meta` and `load.Schema` from `github.com/coder/acp-go-sdk/cmd/generate/internal/load`, and the method grouping comes from `github.com/coder/acp-go-sdk/cmd/generate/internal/ir`.
`jenwrap.go` re-exports jennifer names under short aliases so the emitter does not need a dot-import.

## Interface

- `WriteFiles(outDir string, schema *load.Schema, meta *load.Meta, schemaVersion string) error` calls `WriteConstantsJen`, `WriteTypesJen`, `WriteDispatchJen`, then `WriteHelpersJen`, so that the generator and `stablecheck` write the same files [files.go:WriteFiles]
- `WriteConstantsJen(outDir string, meta *load.Meta, schemaVersion string) error` writes `ProtocolVersionNumber`, `SchemaVersion` (set to `schemaVersion`), and the `AgentMethod<Name>`, `ClientMethod<Name>`, and `ProtocolMethod<Name>` constants to `constants_gen.go`. A method group with no methods gets no const block [constants.go:WriteConstantsJen] [constants_test.go:TestWriteConstantsJen_DeclaresConstants]
- `WriteTypesJen(outDir string, schema *load.Schema, meta *load.Meta) error` writes every schema type plus the `Agent` and `Client` interfaces and one optional single-method interface per other method, such as `AgentLoader` and `AgentUnstableForkSession`, to `types_gen.go` [types.go:WriteTypesJen, emitInterfaces]
- `WriteDispatchJen(outDir string, schema *load.Schema, meta *load.Meta) error` writes `agent_gen.go` (the `AgentSideConnection.handle` switch and the agent-to-client wrappers) and `client_gen.go` (the `ClientSideConnection.handle` switch and the client-to-agent wrappers) [dispatch.go:WriteDispatchJen]
- `WriteHelpersJen(outDir string, schema *load.Schema, meta *load.Meta) error` writes one `New<Union><Variant>` constructor per variant of each eligible `oneOf` union to `helpers_gen.go`. It builds the types with `meta`, so `meta` must not be nil: `ir.BuildMethodGroups` dereferences it [helpers.go:WriteHelpersJen] [types.go:buildTypesJen]
- Type aliases `Code`, `Dict`, `Group`, `File`, and `Statement` for the jennifer types of the same name [jenwrap.go:Code, Dict, Group, File, Statement]
- Function variables that alias jennifer functions: `NewFile`, `Id`, `Lit`, `Line`, `Func`, `For`, `Range`, `Return`, `Nil`, `String`, `Int`, `Float64`, `Bool`, `Any`, `Map`, `Index`, `Qual`, `Error`, `Case`, `Default`, `Switch`, `Var`, `If`, `List`, `Op`, `Parens`, `InterfaceFunc`, `Comment`, `Values`, `DictFunc` [jenwrap.go:NewFile]
- All other functions are unexported. The `j*` helpers build the bodies of the generated `handle` switch cases [dispatch_helpers.go:jUnmarshalValidate, jOptionalAssert]

## Invariants

- Every generated file declares package `acp` and starts with the header `Code generated by acp-go-generator; DO NOT EDIT.` [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]
- Method keys, definition names, and struct property names are sorted before emission [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]. The union property scans use sorted keys too: the string-const properties that a variant's `MarshalJSON` injects, and the fallback discriminator scan described below. Output does not depend on Go map iteration order, provided that each wire name has one method key and each side and method has at most one definition per `Request`, `Response`, or `Notification` suffix. Otherwise the dispatch constant lookup and the `ir` method grouping keep whichever match the map loop sees last [types.go:emitUnion, sortedPropertyKeys, firstConstPropertyKey] [dispatch.go:WriteDispatchJen] [union_test.go:TestWriteTypesJen_MultiConstUnionIsDeterministic]
- Method constant names are `AgentMethod`, `ClientMethod`, or `ProtocolMethod` plus `toExportedConst(key)`, which title-cases each `_`-separated part of the meta key. The dispatch switch cases use the same names, so the two files must stay in step [constants.go:toExportedConst] [dispatch.go:WriteDispatchJen]
- Dispatch skips a meta method that has no group in `ir.BuildMethodGroups`, and skips a switch case whose body is empty. Unknown methods reach the `default` case, which returns `NewMethodNotFound` [dispatch.go:WriteDispatchJen]
- Each generated handler case unmarshals `params` into the Request or Notification type and calls `Validate()`. A failure in either step returns `NewInvalidParams` [dispatch_helpers.go:jUnmarshalValidate, jInvInvalid]
- Errors from the agent or client method are wrapped with `toReqErr` [dispatch_helpers.go:jRetToReqErr]
- A method with an optional interface (`ir.MethodInfo.Optional`) asserts that interface on the agent or client after `Validate`. A failed assertion returns `NewMethodNotFound` [dispatch_helpers.go:jOptionalAssert]
- The response type name is the request name with `Request` replaced by `Response`. When `ir.IsNullResponse` is true for that definition, the interface method returns only `error` and the outbound wrapper calls `SendRequestNoResult` [dispatch.go:WriteDispatchJen] [types.go:WriteTypesJen]
- The generated agent `session/prompt` case derives `context.WithCancel(ctx)`, calls `registerPrompt`, calls the agent with the derived context, and then calls the func that `registerPrompt` returned, which removes the `sessionCancels` entry only while it still belongs to this prompt [dispatch.go:WriteDispatchJen] [agent.go:registerPrompt]
- The generated agent `session/cancel` case calls `a.cancelPrompt` for the session after validation and before the agent's `Cancel` method [dispatch.go:WriteDispatchJen]
- The generated client `Prompt` wrapper sends `Cancel` with `context.Background()` and ignores its error when the request fails and `ctx.Err()` is non-nil [dispatch.go:WriteDispatchJen]
- Outbound notification wrappers are named `SessionUpdate` for `session/update` and `Cancel` for `session/cancel`. Other names drop the `Notification` suffix, and request wrappers drop the `Request` suffix [dispatch.go:WriteDispatchJen]
- `WriteTypesJen` registers every schema definition name in `usedTypeNames` before emission. Nested names and titled or discriminated variant names come from `generateNestedTypeName`, which resolves a taken name with the full `<Parent><Field>` name, then an `Inline` suffix, then numbered suffixes, and panics only when no unique name is left. The `BUG` panics fire when a registration check fails: a generated name that is already registered, an untitled `<Union>VariantN` name that is already taken (it has no fallback), or a variant type emitted without registration [types.go:generateNestedTypeName, WriteTypesJen, emitUnion] [structs.go:emitNestedStructs]
- An `enum`, a `oneOf` of string consts, or an "open" `anyOf` of plain string schemas with at least one string const becomes a named `string` type with constants, not a union wrapper [types.go:WriteTypesJen, classify, emitEnum, isStringConstUnion, isOpenStringEnum]
- Each constant of such a type takes the description of its `oneOf` or `anyOf` alternative as its doc comment, so an unstable value such as `SessionConfigOptionCategorySpeed` says `**UNSTABLE**`. A constant of an `enum` value takes its note in `Definition.EnumNotes`, which the merge sets for a value that only the unstable schema has [types.go:emitEnum, constDocs] [rawjson_test.go:TestWriteTypesJen_EnumConstantsCarryTheirDescriptions, TestWriteTypesJen_EnumConstantsCarryTheirNotes]
- A closed enum that has the member `other` gets an `UnmarshalJSON` that reads every string the enum does not list as that member. The Rust schema crate marks the member `#[serde(other)]`, which the JSON schema does not say, so the member's name is the rule. A value that is no string is an error, and `null` leaves the value as it is. `ToolKind` is the only such enum in schema 0.13.5 through 1.32.0 [types.go:emitEnum, hasOtherMember] [hints_test.go:TestWriteTypesJen_EnumWithOtherReadsUnknownValuesAsOther]
- `emitStruct` declares every generated struct from `ir.Fields`: a top-level object definition, the struct of an inline object property, and the struct of an inline object variant of a union. The rules below hold for all three [structs.go:emitStruct, emitNestedStructs] [types.go:buildTypesJen, emitUnion] [decode_test.go:TestWriteTypesJen_StructDecodesDefaultsAndNamesTypeErrors]
- No generated type holds a value that `encoding/json` decodes into `any`, which rounds an integer above 2^53 to a `float64`. A value that the schema leaves free (no `type`, `{}`, a `$ref` outside `$defs`, or a union that is not a `$defs` entry) is `json.RawMessage`, which keeps the JSON as it was read. An object property without properties is a map: of `json.RawMessage` when `additionalProperties` is `true`, absent, or a schema without a keyword that constrains a value (such as `{}`), and otherwise of the Go type of that schema, as `map[string]ElicitationPropertySchema` for `properties` of `ElicitationSchema` and `map[string]string` for `env` of `AuthMethodTerminal`. A `_meta` property with such free members is `Meta`, the `map[string]json.RawMessage` that the hand-written `meta.go` declares. A `json.RawMessage` that a lenient decoder does not reset keeps an explicit `null`, as `data` of `UnstableMcpError` does [types.go:jenTypeFor, rawJSON, memberType, freeMembers, leavesFree] [structs.go:fieldType] [meta_test.go:TestOpaquePayloads_RoundTripEveryDigit]
- An integer schema has the Go type of the Rust type that its `"format"` names: `int32`, `int64`, `uint16`, `uint32` or `uint64`, and `int` without a format (no schema from 1.18.0 through 1.33.0 has one). So `encoding/json` reads the values that serde_json reads into the Rust type and fails the others, at every site and on every target: `-1` or `-0` in a `uint32`, `2^32` in a `uint32`, `2^31` in the `int32` of `ErrorCode`, and a fraction such as `1.0` anywhere, while a `uint64` takes every value up to 2^64-1. The values that need the width: the `Integer` variant of `ElicitationContentValue`, the bounds and default of `IntegerPropertySchema`, `RequestIdNumber` and `size` of a resource link (`int64`), an exit code (a Windows process that crashes exits with 3221225477), `line`, `limit` and the length bounds of form fields (`uint32`), and the item bounds of form fields, an output byte limit, and token and context counts (`uint64`). `formatTypes` holds the Go type of each format; the generator panics on an integer format that it does not list [types.go:integerType] [ranges.go:formatTypes, formatType] [ranges_test.go:TestWriteTypesJen_PanicsOnAnUnknownIntegerFormat] [rawjson_test.go:TestWriteTypesJen_FreeFormValuesAreRawJSON] [integer_test.go:TestIntegers_HoldEveryValueOnA32BitTarget, TestIntegers_ReadTheRangeOfTheirFormat]
- A patch field (`ir.PatchFields`) is a field of type `Patch[T]`, the type that the hand-written `patch.go` declares, where `T` is the Go type of its schema without `null`. It has no `omitempty`. The struct gets a generated `MarshalJSON` that encodes a local struct with the same fields, in which each patch field is a `*Patch[T]` with `omitempty` that is nil when the patch is unset, so an unset patch is left out and a null one writes `null`. A patch field with `x-deserialize-default-on-error` decodes with `decodePatch` (`decodePatchItems` with `x-deserialize-skip-invalid-items` as well): absent leaves it, `null` makes it null, and a value that does not decode or fit the shape check leaves it unset. Without hints, `Patch.UnmarshalJSON` decodes it and a bad value is an error. A patch field without hints whose items must not be `null` (see below) decodes from its raw property with `Patch.UnmarshalJSON` too, after that check. The doc of a patch field that has no clear (`ir.NullAsAbsent`) ends with a paragraph that says to treat `IsNull` like `IsUnset` there [structs.go:fieldDecls] [rawjson_test.go:TestWriteTypesJen_NullAsAbsentPatchFieldSaysSo]. A patch field with a default, `x-deserialize-default-on-null`, or `x-deserialize-skip-invalid-items` alone panics, because no schema from 0.13.5 through 1.32.0 has one [structs.go:planFor, fieldDecl, patchValueType, emitStruct] [decode.go:decodeStmt, emitSupport] [patch_test.go:TestPatch_RoundTripsAbsentNullAndValue]
- Optional struct fields get a `json:",omitempty"` tag option. Required fields do not. Exception: an optional array or object field whose default is nilable (a slice or map) gets no `omitempty`, so it is always present [structs.go:fieldDecls, planFor]
- A struct gets a generated `MarshalJSON` when a field has a fallback: a schema default, or `[]` for a required array whose schema type does not include `null`. `MarshalJSON` writes the fallback for a nil slice or map, so such a required array never encodes as `null` [structs.go:emitStruct, planFor, emitFillNil] [hints_test.go:TestWriteTypesJen_RequiredArrayIsNeverNull]
- A struct gets a generated `UnmarshalJSON` when a property is required, has a schema default or an `x-deserialize-*` hint, or holds items or member values that must not be `null`. `UnmarshalJSON` applies the default when the key is missing, or when the value is `null` and either the schema type does not include `null` or the property has `x-deserialize-default-on-null` [structs.go:emitStruct, planFor] [decode.go:decodeStmt]
- That `UnmarshalJSON` decodes the object once, into a local struct type that embeds a pointer to the struct without its methods (`*plain`) and keeps each of those properties as `json.RawMessage`. The other properties decode in place, so a property that the JSON does not name keeps its value. A required property is set to zero first (see the required-property rule below). When the decode fails, the properties that decoded before the bad one keep their new values, so a reused value can be partly changed. Each raw property is then decoded with one of the generic helpers `decodeField`, `decodeLenient`, `decodeItems`, and `decodeLenientItems`, which `types_gen.go` declares after the interfaces, next to `rejectNullItems`, when a struct needs one. A defaulted property that the JSON does not name reads as its default, whatever the field held before. The helper `setDefault` decodes the default into a new value for that. A raw property matches its JSON key without regard to case, as every field does in `encoding/json`, so `ReadTextFile` sets `readTextFile` [decode.go:emitDecodeFields, decodeStmt, emitSupport] [decode_test.go:TestWriteTypesJen_StructDecodesDefaultsAndNamesTypeErrors]
- A property with `x-deserialize-default-on-error` never fails the message. A value that does not decode as the field's type reads as the fallback, or as the Go zero value when the field has none. So does a value that decodes but does not fit the shape of the property's schema (next rule). A closed enum field without the hint keeps an unknown value. An enum with the member `other` reads its unknown strings as `other` [decode.go:decodeStmt, emitSupport] [structs.go:planFor] [hints_test.go:TestWriteTypesJen_StructHonorsDeserializeHints, TestWriteTypesJen_EnumWithOtherReadsUnknownValuesAsOther]
- A shape holds the rules of a schema node that the Go types do not check, as the Rust types read them: the kinds of value, an enum or a const, the required members, the members, the map values (`additionalProperties`, which do not apply to a named member, even one that takes every value), the items, the alternatives of an `anyOf` or `oneOf` (one must fit), and `not`. An `allOf` that wraps one `$ref` stands for that `$ref`, and no schema from 0.13.5 through 1.32.0 has another `allOf`. A member with `x-deserialize-default-on-error` takes every value, a member with `x-deserialize-skip-invalid-items` takes every item, and a member with `x-deserialize-default-on-null` takes null, because the Rust types read them as their hints say and keep the value around them. An enum with the member `other` takes every string. An enum or a const that holds an array or an object adds no rule. The boolean schema `false` fits no value, and so does a node whose `not` is `true` or `{}`, as JSON Schema 2020-12 says (sections 4.3.2 and 10.2.1.4). The rules of a node and of its alternatives must all hold: an enum next to an `anyOf` of consts takes the values in both. An integer schema with a `minimum` or `maximum` that its Go type does not enforce (`ownRange`: a bound above the least or below the greatest value of the type; a node without a type of its own, such as a `$ref` or an `allOf` of one with a `minimum` next to it, is an integer when the schema it stands for is one) takes only the integers within it (`ints`, where `math.MinInt64` and `math.MaxInt64` stand for no bound, so a `uint64` above `math.MaxInt64` fits a range without a maximum); the values of an enum or a const decide alone. No schema from 1.18.0 through 1.33.0 has such a bound: each is the range of its format, which the Go type holds, so a hinted `uint32` of -1 reads as absent because it does not decode. The generator panics on a bound that an `int64` cannot hold. String formats, such as `uri`, and `minLength` and `minItems` are not checked: the Rust types do not check them either. `decodeLenient` and `decodeItems` check each decoded value against its shape with `shapeID.accepts`, which the hand-written `shape.go` in the SDK root declares [shapes.go:shapeTable.node, member, alternatives] [ranges.go:ownRange] [shapes_test.go:TestWriteTypesJen_HintedValuesFitTheirSchema] [notbool_test.go:TestWriteTypesJen_NotWithABooleanSchema] [ranges_test.go:TestWriteTypesJen_ValidateChecksIntegerRanges]
- `WriteTypesJen` declares one `shapeID` constant, `shape<Def>`, for each `$defs` entry that a lenient decoder's shape reaches, and the table `shapes` of their shapes, sorted by name. A hinted property whose shape is not one `$ref` gets the constant `shape<Struct><Field>`, with a number appended when a `$defs` entry or another property has that name. A decoder names a shape only when it can reject a value that the Go type decodes: a required member, an enum or a const, an integer out of range, a member or item that must not be null, `not`, or more than one alternative besides null, at any depth. A cycle of `$ref`s adds no rule of its own. When the Go type holds any value (`json.RawMessage`, `Meta`, or a map or slice of either), the kinds count too, beyond an object for a map and an array for a slice. Null at the hinted property itself is a bad value already, so the shape of `anyOf: [X, null]` there is the shape of `X`. When no decoder names a shape, `shapes` is empty, so that `shape.go` compiles [shapes.go:shapeTable.site, strict, emit] [structs.go:planFor] [decode.go:emitSupport]
- An array or map property whose items or member values have a scalar Go type (a string, a number, or a boolean, or a `$defs` entry that is a string enum or a defined type of one of them) rejects a `null` item or value, unless the item or value schema accepts `null` (`acceptsNull`) or the property has `x-deserialize-default-on-error` or `x-deserialize-skip-invalid-items`. `encoding/json` reads such a `null` as `""`, `0`, or `false`, where the schema allows no `null` and the Rust SDK fails the message: `args`, `env`, `headers`, `additionalDirectories`, and the `enum` and `required` strings of an elicitation schema. `rejectNullItems` checks the raw property before it decodes and returns a `*json.UnmarshalTypeError` with `Value` `null`, which `propertyError` names, so `NewSessionRequest.additionalDirectories` fails with `json: cannot unmarshal null into Go struct field NewSessionRequest.additionalDirectories of type string` and the dispatch answers -32602. A whole `null` reads as before: as the default with `x-deserialize-default-on-null`, and as absent or nil otherwise. A patch field and the own properties of a union wrapper follow the same rule, and so does a title-only array variant of a union, such as `ElicitationContentValueStringArray`: its named slice type gets an `UnmarshalJSON` that runs `rejectNullItems`, so a `null` item fails the variant and the union tries the next one. It leaves out items and values of a struct type, which read `null` as the zero struct, and of a union type, whose `UnmarshalJSON` rejects `null` unless the union has a `null` variant [structs.go:planFor, nonNullItem, scalar] [decode.go:emitDecodeFields, decodeStmt, emitSupport] [types.go:emitUnion] [null_items_test.go:TestWriteTypesJen_ScalarItemsAndValuesMustNotBeNull]
- An array property with `x-deserialize-skip-invalid-items` drops the items that are `null`, that do not decode, or that do not fit the shape of its items. Without `x-deserialize-default-on-error`, a value that is not an array is still an error [decode.go:decodeStmt, emitSupport] [hints_test.go:TestWriteTypesJen_StructHonorsDeserializeHints]
- A required array reads `null` as `[]` when it has `x-deserialize-default-on-null` or `x-deserialize-default-on-error`. The latter also reads a value of the wrong shape as `[]`. An absent required array fails to decode, by the rule below [structs.go:planFor] [hints_test.go:TestWriteTypesJen_RequiredArrayIsNeverNull]
- A required property must be present in the JSON object, and must not be `null` unless its schema accepts `null` (`acceptsNull`) or it has `x-deserialize-default-on-null` or `x-deserialize-default-on-error`, as in the Rust SDK. `encoding/json` leaves such a field at its Go zero value, which `Validate` cannot tell from a present `""`, `0`, `false` or `{}`. The rule holds for every struct of `emitStruct` and for the own fields of a union wrapper, which decode through the same plan. `planFor` decides it once per field (`fieldPlan.required`, `takesNull`). A required property with a schema default is exempt, because the default stands in for it. After the decode, `emitRequireMembers` reads the members of the object (`jsonMembers`) only when a required field may be absent (`maybeAbsent`: its zero value, or `null` for raw JSON), and `requireMember` returns a `*json.UnmarshalTypeError` with `Value` `missing member` or `null`, the field's type, and, through `propertyError`, the struct and the property. A key matches in any case, as `encoding/json` reads it. A JSON `null` where such a struct goes has no members, so it fails too. A union variant without a required member fails to decode, which the union reports as `invalid variant payload`. Such a struct's `UnmarshalJSON` first sets each required field to its zero value, so a field that a reused value holds cannot hide an absent member; the JSON sets every required field on success, and the other fields keep what the value held. A union wrapper starts from an empty wrapper already [structs.go:planFor, emitStruct] [decode.go:emitDecodeFields, emitRequireMembers, emitSupport] [presence_test.go:TestWriteTypesJen_RequiredMembersMustBePresent]
- A `*json.UnmarshalTypeError` from that `UnmarshalJSON` names in `Struct` the struct that the method belongs to, and in `Field` the path of the bad value from that struct: `InitializeResponse` and `agentCapabilities.loadSession`. `encoding/json` builds the same path for structs without the method, but it names the innermost struct, here `AgentCapabilities`. The local type takes the struct's name for that. `plainFieldError` removes the `plain.` that Go 1.24 and later put in front of a property decoded through the embedded pointer, and `propertyError` sets both names for a raw property [decode.go:emitDecodeFields, emitSupport] [decode_test.go:TestWriteTypesJen_StructDecodesDefaultsAndNamesTypeErrors]
- A union wrapper has one pointer field per variant with tag `json:"-"`. Its `UnmarshalJSON` starts from an empty wrapper, so a value that is decoded twice holds only the last payload. JSON `null` selects the `null` variant, and is an error when the union has none. A `null` variant takes no other input. For a JSON object the method then decodes the wrapper's own fields if it has any, and switches on the discriminator. A variant that the switch did not settle and that has required keys, a const property, or a property whose type is `"null"` alone comes next. It matches when the object has the keys, every const property that is present holds its value, and every null-only property is absent or `null`. A required key that is `null` counts as missing, unless its schema accepts `null`, as `id` and `result` in `AgentResponse` do, or the key has `x-deserialize-default-on-null` or `x-deserialize-default-on-error`. The variant reads `null` as the default of such a key, as it does for `args` of a stdio `McpServer` from schema 1.27.0. After that it tries required keys of array items, by the same rule. Last, it tries in order the variants that match by none of these. A variant that is a number, a string, or a boolean with a `const`, such as `-32700` in `ErrorCode`, takes only that value. So a form request without a scope is an error, and so is an unknown discriminator value, unless a variant without a const takes the object, as the stdio variant of `McpServer` does. If nothing matches, it returns `no matching variant for union`. The method reads the discriminator, the required keys, and the const and null-only properties by their exact keys, as the upstream Rust types do. The fields of the selected variant follow `encoding/json`, which also reads a key in another case [types.go:emitUnion, acceptsNull, scalarConstOf] [vet_test.go:TestWriteTypesJen_GeneratedPackagePassesVetAndTests] [discriminator_test.go:TestWriteTypesJen_UnionMatchesAVariantOnlyWithItsConstValue]
- A catch-all variant, such as `other` in `CreateElicitationResponse`, has the discriminator as a required string without a const. It matches only a discriminator that is a JSON string, after the switch found no const for it. A `none` variant, as in `IdleStateUpdate`, has the discriminator as a null-only property and takes an object without it. When the discriminator is a property of the union itself with `x-deserialize-default-on-error`, a value that is neither a string nor `null` reads as absent [types.go:emitUnion] [discriminator_test.go:TestWriteTypesJen_CatchAllAndNoneVariants]
- A struct whose schema says `"additionalProperties": true` or `"unevaluatedProperties": true` gets the field `AdditionalProperties map[string]json.RawMessage` with tag `json:"-"`, and both methods. `UnmarshalJSON` puts there every member whose key matches no property in any case, and leaves the field nil when there is none. It keeps each member as the JSON that it read, so a number keeps every digit. `MarshalJSON` writes those members next to the properties, and a property wins over a member with its key. The catch-all variants and `McpError` are such structs. `emitStruct` panics when a property maps to the field name `AdditionalProperties` [structs.go:emitStruct] [decode.go:emitSupport] [discriminator_test.go:TestWriteTypesJen_CatchAllAndNoneVariants]
- A union whose schema says `"additionalProperties": true` or `"unevaluatedProperties": true`, as the `other` mode of `CreateElicitationRequest`, gets the field `AdditionalProperties map[string]json.RawMessage` with tag `json:"-"` on its wrapper. `UnmarshalJSON` puts there every member of an object whose key matches, in any case, no property of the union and no property of any of its alternatives, at any depth: a `$ref`, an `allOf` and a nested `anyOf` or `oneOf` included. The Rust SDK drops a member that only an alternative other than the selected one names, and so does this rule. `MarshalJSON` adds those members to the object of the set variant, also when the variant is a `$ref`, and a member that the variant or the wrapper writes keeps its value. An inline variant that takes its alternatives from an `allOf` takes `unevaluatedProperties` along `emitUnion` panics when a property or a variant of such a union maps to the field name `AdditionalProperties` [types.go:emitUnion] [vet_test.go:TestWriteTypesJen_GeneratedPackagePassesVetAndTests]
- Every union wrapper gets a `Validate`. A `oneOf` union's returns an error unless exactly one variant is set, and an `anyOf` union's unless one at least is set (`<Union> has no variant set`). It then checks the wrapper's own fields by the rules of the `Validate` bullet below, and returns the error of the set variant's `Validate` as it is, because a variant is the same JSON object, not a member of it. A title-only array variant, such as `SessionConfigSelectOptionsGrouped`, has no `Validate` of its own: the wrapper calls the `Validate` of each item and puts `[i]: ` in front of the error [types.go:emitUnion] [validate.go:validateHeld] [validate_test.go:TestWriteTypesJen_ValidateChecksRequiredMembersAtEveryDepth]
- A union's own properties go one of two ways. When every variant is an inline object (no `$ref`, with its own properties, not `null`), each variant struct gets them and the union's required keys. Otherwise they become fields of the wrapper, next to the variant pointers, because a `$ref` variant is a type of its own that cannot take them. The wrapper's own fields follow the struct rules above for tags, fallbacks, hints, and decoding [types.go:emitUnion, unionAlternatives, allInlineObjects] [vet_test.go:TestWriteTypesJen_GeneratedPackagePassesVetAndTests]
- An inline object variant that has an `anyOf` or `oneOf` of its own, after `allOf` is merged in, becomes a union wrapper in turn. Its properties are that wrapper's own properties, and its alternatives are the variants: `UnstableCreateElicitationForm` has the form mode's fields and a `Session` or `Request` scope [types.go:emitUnion] [vet_test.go:TestWriteTypesJen_GeneratedPackagePassesVetAndTests]
- A union's `MarshalJSON` re-encodes the set variant. For an object variant it also injects the string-const properties. The members of the variant stay raw JSON on the way, so a number keeps every digit [content_block_test.go:TestContentBlock_MarshalJSON_KeepsEveryDigitOfAnInteger]. A wrapper with own fields merges their JSON into the variant's object, and returns the error `<Union> has no variant set` when no variant is set. It returns a `$ref` or title-only variant that does not encode as an object as encoded, because JSON Schema applies the own properties to objects only. In a wrapper without own fields, a non-object variant is returned as encoded, with no code after that return, a `null` variant encodes `null`, and no variant set gives empty output [types.go:emitUnion]
- A definition that matches no other case becomes an alias of `json.RawMessage` (`type <Name> = json.RawMessage`, so it keeps the methods of `json.RawMessage`) with the comment "is a union or complex schema; it holds the JSON as it was read". `ExtRequest`, `ExtResponse`, and `ExtNotification` are such aliases. An object schema with no properties becomes an empty struct. With `"additionalProperties": true` it becomes a struct that has only `AdditionalProperties`. No schema from 0.13.5 through 1.32.0 has such a definition [types.go:WriteTypesJen] [discriminator_test.go:TestWriteTypesJen_CatchAllAndNoneVariants]
- A title-only variant whose description contains "extension" or whose title contains `Ext` becomes an alias of `json.RawMessage`, so the raw payload is kept. A variant with no `$ref`, no properties, no `null` type, and no title is skipped [types.go:emitUnion]
- `Validate` is the inbound check after a message decodes, and serves values built in Go, which the decode rule above does not see. `classify` decides which kind of Go type a `$defs` entry becomes, and `validates`, memoized per entry, is the one owner of the decision whether that type's `Validate` checks something: every union wrapper does (it checks that a variant is set), and a struct does when its check plan (`checkPlan`, one `fieldCheck` per field) is not empty. A `Validate` calls the `Validate` of a value only when `validates` says that its type has one, so it never calls a missing method. A message type (`*Request`, `*Response`, or `*Notification`, an empty object included) always gets a `Validate`, which returns nil when its plan is empty, because the dispatch calls it; no other type gets one that checks nothing. The plan follows what the Rust SDK rejects. A required member whose Go type is a named string type of the schema (a `$ref` or `allOf` to a string, a closed enum, or an open one) must not be `""`, and a required array must not be nil, at every depth: `PromptRequest.Validate` checks `sessionId`, and `McpServerAcpInline.Validate` checks `serverId`. A required plain inline string must not be `""` only in a message type, and, for the union's own properties, in the variants of a message-level union: `CreateElicitationRequest.Validate` rejects a set `Form` or `Url` variant with an empty `Message`, while `TextContent.text` and the `name` of a `SessionConfigOption` may be `""`. A `const` property, a property with a default, one whose schema accepts `null`, and a patch field get no such check, nor do integers, numbers, and booleans. A field whose type has a `Validate` descends into it: a pointer when it is not nil, each item of a slice and member of a map, a `Patch` when it is set, and a struct or union value only when the member is required, because an absent optional one looks like its zero value. A lenient field (`x-deserialize-default-on-error` or `x-deserialize-skip-invalid-items`) does not descend, because Rust reads a bad value there as the default; the nil check of a lenient required array stays. A descent puts the path of the value in front of the error: `toolCall: toolCallId is required`, `mcpServers[0]: serverId is required`, `content["k"]: ...`. An integer that a field holds the same way, required, through a pointer, an item, a map member or a `Patch`, must be within each `minimum` and `maximum` of its schema and of each schema that stands for it (`heldRange`) that its Go type does not enforce: `narrow must be between 5 and 10`, `tight must be at least 1`. The range of the format needs no check, because the Go type holds it and a value out of it fails to decode, as in Rust; no schema from 1.18.0 through 1.33.0 has another bound, so no generated `Validate` checks a range. A `minimum` or `maximum` that is not integer text, such as `0.5` or `1e1`, rounds inward (`bound`), and a check whose bound does not fit an `int32` compares an `int` as an `int64`, because an `int` is 32 bits wide on some targets. A lenient field checks no range: its shape does. An optional integer whose schema does not take `null` is not a pointer, and its struct writes 0 as an absent member (`omitempty`): its bounds are checked only when it is not 0 (`nonZero`), so an explicit 0 out of them passes. An absent member reads as 0, or as the schema `default` when there is one, so the decoder tells an explicit 0 from absent there, but `Validate` still cannot. The generator panics on an integer `default`, lenient or not, that is not an integer within its format and its bounds, or that is 2^53 or beyond, which `load` may have rounded when it read it as a `float64` (`mustHoldDefault`). Such a default fills an absent member that `Validate` would then reject, or that `setDefault` reads as 0, and the Rust SDK fills it unchecked. No schema from 1.18.0 through 1.33.0 has an optional integer of this kind or an integer default. `minLength`, `minItems` and string formats are not checked. A `$ref` cycle reads as no `Validate` while `validates` decides it; schema 1.32.0 has none [validate.go:checkPlan, fieldCheckFor, validates, emitChecks, validateHeld, eachHeld] [ranges.go:heldRange, checkRange, mustHoldDefault] [types.go:classify, buildTypesJen, emitUnion] [structs.go:emitStruct] [validate_test.go:TestWriteTypesJen_ValidateChecksRequiredMembersAtEveryDepth] [ranges_test.go:TestWriteTypesJen_ValidateChecksIntegerRanges, TestWriteTypesJen_ValidateChecksOptionalIntegers, TestWriteTypesJen_PanicsOnADefaultOutsideItsBounds] [vet_test.go:TestWriteTypesJen_GeneratedPackagePassesVetAndTests]
- `Agent` and `Client` are always emitted, even when empty. Each optional interface follows its side's interface, in meta key order. `emitInterfaces` panics when the name of an optional interface is already a generated type name [types.go:emitInterfaces] [interfaces_test.go:TestWriteTypesJen_StabilizedMethodStaysOutOfAgent, TestWriteTypesJen_PanicsWhenAnOptionalInterfaceNameIsTaken]

## Side Effects

- Writes `constants_gen.go`, `types_gen.go`, `agent_gen.go`, `client_gen.go`, and `helpers_gen.go` into `outDir` with `os.WriteFile`. A missing file is created with mode `0o644` (before umask). An existing file is truncated and keeps its permissions [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]
- `WriteDispatchJen` writes `agent_gen.go` before it renders `client_gen.go`, so a later failure leaves `agent_gen.go` written [dispatch.go:WriteDispatchJen]
- Returns render and write errors to the caller [constants.go:WriteConstantsJen] [types.go:WriteTypesJen] [dispatch.go:WriteDispatchJen] [helpers.go:WriteHelpersJen]
- `WriteTypesJen` and `WriteHelpersJen` return the error of `schema.RefLoop` before they build anything, because their walkers follow a `$ref` loop forever: `fitsNull`, `expandAllOf` and `acceptsNull` at generation, and `shape.fits` at decode time [types.go:WriteTypesJen] [helpers.go:WriteHelpersJen] [refloop_test.go:TestWriteTypesJen_RejectsARefLoop]
- Panics when no unique nested name is left, when an untitled `<Union>VariantN` name is already taken, when a registration check fails, when an own property of a union and one of its variants map to the same wrapper field, when the name of an optional interface is already taken, or when a schema default does not encode as JSON [types.go:generateNestedTypeName, emitUnion, emitInterfaces] [structs.go:emitNestedStructs, planFor]
- No network, subprocess, environment, goroutine, or lock use in the emitter itself. At run time, the generated code locks `a.mu`, calls the generic function `SendRequest[T](c.conn, ...)`, and calls the methods `c.conn.SendNotification` and `c.conn.SendRequestNoResult` [dispatch.go:WriteDispatchJen]
